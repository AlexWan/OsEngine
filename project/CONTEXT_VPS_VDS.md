# CONTEXT_VPS_VDS — Удалённые серверы для OsEngine

> Назначение: как развернуть и эксплуатировать боевых роботов OsEngine на удалённом сервере (VPS/VDS). Только тема удалённых серверов: выбор провайдера, первичная настройка Windows, оптимизация, безопасность, регламент эксплуатации.
>
> Общая карта всех контекстов проекта — в файле [`CONTEXT.md`](CONTEXT.md).

---

## 1. Зачем торговать удалённо

### 1.1. Почему нельзя торговать роботами с домашнего ПК

Торговля роботом с домашнего компьютера несёт технологические риски:

- внезапное отключение электричества;
- отвал интернета / Wi-Fi;
- домашние случайно выключат компьютер;
- обновления Windows уведут машину на перезагрузку посреди сессии.

При остановке робот перестаёт контролировать открытые позиции — это прямой путь к убыткам. Для ручной торговли «от случая к случаю» домашний ПК допустим, для роботов — нет. Удалённый сервер сводит эти риски практически к нулю, а по стоимости это недорого.

### 1.2. Минимальные требования к серверу

| Компонент | Минимум |
|-----------|---------|
| Процессор | от 2 ядер |
| Оперативная память | от 3 ГБ |
| Хранилище | SSD от 15 ГБ |

### 1.3. Базовые правила эксплуатации

1. **Отключите обновления Windows** на сервере, чтобы он не уходил на перезагрузку посреди торгов.
2. **Часовой пояс:** торгуете криптовалютой — выставляйте UTC; торгуете на MOEX — московское время.
3. **Провайдеры тоже падают.** За прошлые годы команда минимум три раза сталкивалась с отключениями на стороне VDS-провайдера. На этот случай у вас должен быть способ закрыть все открытые позиции на бирже вручную (с телефона или другого устройства).
4. **Регламент контроля:** заходить на сервер и проверять роботов нужно 1–3 раза в неделю.

## 2. VPS для MOEX — Cloud4box

### 2.1. Что использует команда

На конец 2025 года роботы команды OsEngine для MOEX работают на **Cloud4box** (серверы в Москве). Это не утверждение, что провайдер самый лучший/быстрый/дешёвый — это факт текущего боевого использования по совокупности обстоятельств.

- Промоссылка: `https://cloud4box.com/?from=92500`
- Промокод: `3369_92500`

### 2.2. Выделенный сервер vs VPS

У Cloud4box интересуют две услуги:

| Тип | Что это | Когда брать |
|-----|---------|-------------|
| **Выделенный сервер** | Отдельная физическая машина в серверной провайдера, без виртуализации и деления мощностей с другими клиентами | Торговля в полный рост на 5–20 счетах и разных биржах; оптимизация и тестирование; развёртывание Visual Studio для полноценного кодинга прямо на сервере. Выбор команды |
| **VPS/VDS** | Виртуальная машина, мощности делятся с другими пользователями, но сильно дешевле | Один боевой OsEngine без кодинга и оптимизации. Можно и нужно использовать для боевой торговли |

## 3. VPS для крипты — is*hosting (Япония)

### 3.1. Провайдер и локация

Для крипты команда использует **is*hosting**, локация — **Япония** (близость к серверам криптобирж). Для MOEX этот провайдер не используется — см. раздел 2.

- Аффилированная ссылка команды: `https://ishosting.com/affiliate/Mjk3NyM2`

### 3.2. Выбор тарифа

| Тариф | Сценарий |
|-------|----------|
| Medium | Один терминал OsEngine, малая нагрузка |
| Premium | Два и более терминалов одновременно |

При заказе выбирается локация (Япония) и платформа Windows. В окне «Конфигурация виртуального сервера» параметры можно менять под себя.

### 3.3. Пошаговая процедура аренды

1. Перейти по ссылке на официальный сайт, в правом верхнем углу нажать «Личный кабинет».
2. Вбить электронную почту, нажать «Продолжить».
3. Пройти стандартную регистрацию: пароль, повтор пароля, галочки соглашений, подтверждение почты по ссылке из письма.
4. В личном кабинете открыть «Мои виртуальные серверы» (или «Добавить услугу»).
5. Выбрать локацию Япония, платформу Windows, тариф Medium/Premium, нажать «Выбрать».
6. При необходимости скорректировать конфигурацию, добавить в корзину.
7. Оформить заказ, заполнить форму, выбрать способ оплаты и оплатить.
8. Дождаться письма на почту с описанием сервера и его данными. **Сохранить эти данные!**

## 4. Подключение к серверу по RDP

Подключение выполняется стандартным клиентом Windows «Подключение к удалённому рабочему столу»:

1. На домашнем Windows в строке поиска (Пуск) начать вводить слово «удаленный».
2. Выбрать «Подключение к удалённому рабочему столу».
3. Заполнить поля данными из письма провайдера: IP, имя пользователя, нажать «Подключить».
4. Ввести пароль, нажать «OK».

Подключение выполнено — вы на рабочем столе сервера.

### 4.1. Практические замечания по RDP

- Сохраните параметры подключения в `.rdp`-файл («Сохранить как» в окне подключения) — не придётся каждый раз вбивать IP и логин.
- Письмо провайдера с IP/логином/паролем — единственная точка входа. Потеряли письмо — идёте в личный кабинет провайдера за сбросом пароля.
- Разрыв RDP-сессии (закрытие окна крестиком) **не останавливает** роботов: сессия на сервере продолжает жить. Не путать с завершением сеанса («Sign out») — его избегайте, если автозапуск не настроен.
- За разрывами RDP со стороны домашнего интернета следить не нужно: важна только связь «сервер → биржа», она от вашего ПК не зависит.

## 5. Первичная настройка Windows Server

### 5.1. Русификация Windows Server 2022

Если сервер пришёл без русскоязычного пакета, а работать в англоязычной версии некомфортно:

1. Пуск → «Параметры» (значок шестерёнки).
2. «Time & Language» → «Language».
3. Нажать значок плюсика (добавить язык).
4. В поиске набрать «Ру», выбрать «Русский», «Next».
5. Поставить галочку установки языкового пакета, нажать «Install».
6. Дождаться установки и перезагрузить сервер.

### 5.2. Часовой пояс

- MOEX → московское время.
- Крипта → UTC.

### 5.3. Автоматическая синхронизация времени — Dimension 4

На VPS время ОС постепенно расходится с временем биржи. Рассинхрон даже в несколько десятков миллисекунд приводит к тому, что биржа отказывается совершать часть операций — например, выставлять ордера. Торговля становится невозможной.

Вариант «раз в несколько дней синхронизировать время вручную» работает плохо. Решение — программа **Dimension 4**, ставится один раз на каждый удалённый сервер и дальше синхронизирует время автоматически:

1. Скачать: `http://www.thinkman.com/dimension4/download.htm`
2. Установить (стандартный установщик, на всё соглашаемся), включить.
3. В настройках задать частоту обновления и свернуть программу. **Чаще 1 раза в 10 минут обновлять не надо.**

### 5.4. Отключение обновлений Windows

Обновления системы на боевом сервере отключаются, иначе сервер уйдёт на перезагрузку в произвольный момент — см. 1.3.

## 6. Оптимизация производительности сервера

### 6.1. Отключение Antimalware Service Executable (−30% ЦП)

«Antimalware Service Executable» — компонент встроенного антивируса Windows, который съедает много ресурсов (ЦП и память). Его отключение в ряде случаев снижает нагрузку на ЦП до 30%.

> **Важно!** Прежде чем отключать встроенную защиту, установите другой антивирус, если его ещё нет.

Процедура через редактор групповой политики:

1. Пуск → в поиске вбить `gpedit.msc` → открыть.
2. «Конфигурация компьютера».
3. «Административные шаблоны» (развернуть).
4. «Компоненты Windows» (развернуть).
5. «Антивирусная программа» (развернуть).
6. Папка «Защита в реальном времени».
7. В правой части поочерёдно открыть каждую запись и перевести в состояние «Отключено»: флажок «Отключено» → «Применить» → «OK».

### 6.2. Приоритет процессора на приложения

По умолчанию сервер может быть настроен на приоритет фоновых задач, а не приложений. Исправление:

1. Пуск → Панель управления.
2. «System and Security» → настройки системы.
3. «Дополнительные настройки системы».
4. Вкладка «Расширенные» → в блоке быстродействия (визуальные эффекты, файл подкачки) нажать «Настроить».
5. Вкладка расширенных настроек → выбрать приоритет процессора на **приложения** → «Apply».

### 6.3. Файл подкачки

Если файл подкачки не настроен, при переполнении оперативной памяти сервер просто перезагружается — с живыми позициями в роботах.

1. Там же: Панель управления → «System and Security» → «Дополнительные настройки системы» → «Расширенные» → «Настроить» (быстродействие).
2. Перейти в меню настройки файла подкачки.
3. Выбрать «настраиваемый объём», задать размер, нажать «Установить».

После этих настроек ОС работает заметно стабильнее.

## 7. Безопасность: блокировка интерфейса OsEngine по паролю

### 7.1. Модель угроз

К удалённому серверу имеют доступ ещё N людей: как минимум — сотрудники хостера, как максимум — неопределённый круг злоумышленников. Чтобы в ваше отсутствие никто не мог управлять OsEngine, интерфейс программы блокируется по паролю.

### 7.2. Как заблокировать

1. В BotStation Light в левом нижнем углу нажать значок замка.
2. В открывшемся окне ввести пароль.
3. Нажать «Заблокировать интерфейс».

Что блокируется:

- просмотр данных в нижних вкладках;
- открытие панелей роботов;
- закрытие программы.

Блокировка устойчива к «хитрости» с убийством процесса: если закрыть программу через диспетчер задач и перезапустить, главное меню останется заблокированным.

### 7.3. Как разблокировать

Нажать на закрытый замок в любом месте приложения → ввести пароль в меню разблокировки → интерфейс снова работает.

## 8. Эксплуатация и аварийные сценарии

### 8.1. Регламент

- Заходить на сервер 1–3 раза в неделю.
- Проверять: роботы запущены и торгуют, соединение с биржей живо, время синхронизировано, свободные RAM/диск в норме.

### 8.2. Сервер недоступен / провайдер упал

1. Не паниковать: позиции на бирже остались открытыми и неконтролируемыми.
2. Закрыть позиции вручную: приложение брокера/биржи с телефона или другого устройства.
3. Связаться с провайдером, дождаться восстановления.
4. После восстановления: проверить время (Dimension 4), перезапустить роботов, сверить позиции.

### 8.3. Сервер перезагрузился (обновление, переполнение RAM, сбой хостера)

1. Зайти по RDP, проверить причину в журнале событий Windows.
2. Если причина — обновления Windows: отключить их (см. 5.4), чтобы не повторилось.
3. Если причина — переполнение памяти: настроить/увеличить файл подкачки (см. 6.3) и разгрузить ЦП (см. 6.1).
4. Запустить OsEngine, убедиться, что коннекторы переподключились к бирже.
5. Сверить позиции роботов с фактическими позициями на бирже — за время простоя они могли разойтись.
6. Проверить синхронизацию времени перед возобновлением торговли.

### 8.4. Профилактика раз в неделю

- Роботы в списке BotStation активны и не в ошибках.
- Логи без повторяющихся исключений.
- RAM и диск не под завязку (иначе — раздел 6).
- Часы сервера совпадают с биржевым временем.

## 9. Чек-лист постановки на удалённый сервер

- [ ] Выбран провайдер под рынок: MOEX → Cloud4box (Москва), крипта → is*hosting (Япония).
- [ ] Тариф соответствует нагрузке: 1 терминал → Medium/VPS, 2+ терминала или 5–20 счетов → Premium/выделенный.
- [ ] Данные сервера из письма сохранены (IP, пользователь, пароль).
- [ ] RDP-подключение работает.
- [ ] Windows русифицирована (по желанию).
- [ ] Часовой пояс: MSK для MOEX / UTC для крипты.
- [ ] Установлена Dimension 4, синхронизация не чаще 1 раза в 10 минут.
- [ ] Обновления Windows отключены.
- [ ] Установлен сторонний антивирус, Antimalware Service Executable отключён через gpedit.
- [ ] Приоритет процессора переключён на приложения.
- [ ] Настроен кастомный файл подкачки.
- [ ] OsEngine перенесён, роботы запущены и торгуют.
- [ ] Интерфейс OsEngine заблокирован по паролю.
- [ ] Есть план ручного закрытия позиций (телефон/другое устройство).

## 10. Частые ошибки

| Ошибка | Последствие | Как правильно |
|--------|-------------|---------------|
| Торговля роботом с домашнего ПК | Неконтролируемые позиции при отключении света/интернета | Только удалённый сервер |
| Один провайдер на оба рынка | Лишние задержки/недоступность | MOEX → Москва (Cloud4box), крипта → Япония (is*hosting) |
| Неверный часовой пояс | Сбои в расписаниях и данных | MSK для MOEX, UTC для крипты |
| Нет синхронизации времени | Биржа отклоняет ордера при рассинхроне в десятки мс | Dimension 4 на каждый сервер |
| Синхронизация времени чаще 10 минут | Лишняя нагрузка, не нужно | Не чаще 1 раза в 10 минут |
| Обновления Windows включены | Перезагрузка посреди сессии | Отключить |
| Отключён Defender без замены | Голый сервер | Сначала другой антивирус, потом gpedit |
| Нет файла подкачки | Ребут при переполнении RAM | Кастомный объём |
| Данные сервера из письма потеряны | Нет доступа к своей машине | Сохранить сразу |
| Интерфейс не заблокирован | Управление роботами доступно хостеру/чужим | Замок в BotStation Light |
