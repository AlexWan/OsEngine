# CONTEXT_OSTESTER_TESTSTAND — тестовый стенд тестера (консольная программа)

> Описание тестового стенда `OsEngine.OsTester.TestStand` — детерминированная проверка тестера
> (TesterLight) через MCP OsEngine. Стенд доступен внешним агентам для штатного авто-теста тестера.

## 1. Цель

Дать внешним агентам (Мастер Tester) готовый инструмент проверки тестера, чтобы агент
**не выдумывал проверки заново** на каждом запуске, а:
1) запускал стенд (стенд сам поднимает OsEngine в режиме `testerlight`);
2) получал структурированный отчёт pass/fail по проверкам;
3) интерпретировал результат и отчитывался / эскалировал.

## 2. Расположение и имя

- Путь: `project\Tests\OsTesterTestStand\OsEngine.OsTester.TestStand\`.
- Имя проекта: `OsEngine.OsTester.TestStand` (`.csproj`, `net10.0`, консоль).
- Работает только через MCP OsEngine — **без прямой ссылки на OsEngine**.

## 3. Как устроен

- `Program.cs` — вход: лог-файл, парсинг аргументов, запуск OsEngine с `-testerlight`, перебор модулей.
- `OsEngineProcessController.cs` — запуск/остановка OsEngine, ожидание MCP-порта.
- `McpApiClient.cs` — MCP-клиент (`ToolsCall`, V1/V2).
- `TestContext.cs` — отчётность (`RecordPass/RecordFail/PrintSummary`), маскирование секретов.
- `TestResult.cs` — pass/fail.
- `TestSecrets.cs` — ключи/токены (не в git).
- `ProtocolValidator.cs` — валидация JSON-RPC/MCP (протокольные отклонения, не фейлы).
- `Tests/OsTesterTestsBase.cs` — общая база: вызовы MCP, разбор ответов, ожидание конца прогона, сброс настроек.
- `Tests/DataPreparation.cs` — подготовка данных (качает недостающие сеты через OsData).
- `Tests/*.cs` — модули тестов (см. п. 4).

> **За основу взят тестовый стенд OsData** (`OsEngine.OsData.TestStand`, `project\Tests\OsDataTestStand\…`):
> переиспользуется его инфраструктура (`McpApiClient`, `OsEngineProcessController`, `TestContext`,
> `TestSecrets`, `TestResult`, `ProtocolValidator`) — меняются только namespace и тесты.
>
> Код пишется **по правилам OsEngine** (`project\CONTEXT_CODING_GUIDELINES.md`): преамбула с лицензией
> у каждого `.cs`, явные типы без `var`, `#region` для крупных классов, try-catch с логированием вместо
> пустых `catch`, русские комментарии — только внутри методов.

## 5. Как запускать

```bash
dotnet run -- [--module/-m NAME] [--set TesterSBER] [--port 6500] [--api-key KEY] [--timeout 60] [--no-wait] [--transport v1|v2]
```

- `--module/-m` — фильтр модулей (имя или номер, через запятую). Без флага — все 8 модулей разом.
- `--set` — имя сета данных (по умолчанию `TesterSBER`).
- `--port` / `--api-key` — MCP OsEngine (по умолчанию `6500` / `osengine-mcp-default-key`).
- `--timeout` — таймаут ожидания MCP после запуска OsEngine (сек).
- `--no-wait` — неинтерактивный режим (не спрашивать секреты).
- `--transport v1|v2` — транспорт MCP (по умолчанию v2, Streamable HTTP).

Пример — один модуль:

```bash
dotnet run -- -m Simple --set TesterSBER
```

## 6. Что на выходе

Во время прогона — построчно `[Module N] ...` + `Status: PASS/FAIL - ...`. В конце — сводка:

```
--- Module Summary ---
Simple: 7/7 passed
...

Total: 46/46 passed in 861.5s

--- Protocol Violations ---
none
```

- `Total: X/Y passed` — главный итог; при `> 0` failed стенд завершается с **ненулевым кодом выхода**.
- `--- Protocol Violations ---` — отклонения от протокола MCP (заголовки/JSON-RPC/статус-коды), не считаются фейлом.
- Вывод дублируется в консоль + лог-файл `ostester-test-stand-yyyyMMdd-HHmmss.log` рядом с `.exe`.

## 8. Примечания

- Стенд работает через MCP OsEngine (`tester_*`, `bot_*`, `bot_journal_*`, `terminal_*`) —
  тот же путь, что и у внешних агентов. Разница: проверки детерминированы и закодированы.
- Штатные роботы: `SmaTrendSample` (BotTabSimple), `SmaScreener` (BotTabScreener), `GridBollinger` (сетка).
- Сеты готовит сам стенд (модуль 1, `DataPreparation`): свечи `TesterSBER`/`Tester10Liq`, тики `TesterTicks`,
  стаканы `TesterDepth`. Недостающий сет качается автоматически.
- Начисления: инструмент `tester_charges_set_config { dividends_is_on, taxes_is_on, margin_regime }`
  (добавлен в MCP OsEngine) включает/выключает дивиденды, налоги и маржу. Маржа также зависит от
  `portfolio_calculation_enabled` (`tester_portfolio_set_config`).
- Ключи/токены — в `test-secrets.json` (не в git), по образцу `McpApi.TestStand`/`OsData.TestStand`.
