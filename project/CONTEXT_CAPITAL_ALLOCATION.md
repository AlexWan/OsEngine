# CONTEXT_CAPITAL_ALLOCATION — Аллокация капитала

> Модуль группировки ботов по корреляции доходностей и распределения капитала между ними.
> Для ИИ-агентов и разработчиков. Пользовательское имя — «Аллокация капитала» /
> «Capital allocation». В коде — `OsEngine.OsCapitalAllocation` (классы `CapitalAllocation*`),
> MCP-инструменты — `allocation_*`.

## 1. Зачем это нужно

Для тех, у кого много роботов (десятки стратегий на разных инструментах). Держать
одинаковый капитал на похожих роботах — значит не диверсифицироваться: если у стратегий
одна логика/база, их доходности коррелируют, и они одновременно и зарабатывают, и теряют.

Модуль:

1. группирует роботов по корреляции доходностей в **кластеры**;
2. распределяет капитал **между кластерами**, а не по отдельным роботам — чтобы внутри
   одного кластера не было «двойного» риска;
3. отдаёт **веса (доли капитала) на робота** — их можно сохранить в файл и применить к
   реальным ботам (задать объёмы позиций).

## 2. Научное обоснование

- **Современная портфельная теория (MPT, Марковиц, 1952)** — риск портфеля определяется не
  только волатильностью отдельных активов, но и их корреляцией (ковариационной матрицей).
  Диверсификация тем лучше, чем меньше активы коррелированы.
- **Корреляционная кластеризация** — частный случай иерархической агломеративной
  кластеризации (HAC), метрика похожести — корреляция Пирсона. Метод — **complete-linkage**:
  бот попадает в кластер, только если коррелирует выше порога со **всеми** ботами кластера
  (кластер — «клика»). Капитал делится поровну: `1/N` на кластер, внутри — поровну на бота.
- **Иерархический риск-паритет (HRP, Лопес де Прадо, 2016)** — 3 шага:
  Tree Clustering (`d = √(0.5·(1−ρ))` + линковка → дендрограмма) → Quasi-Diagonalization
  (seriation) → Recursive Bisection (веса ∝ 1/дисперсия). Преемник Марковица, решает
  нестабильность классической mean-variance оптимизации.

Оба варианта кластеризуют одинаково (по корреляции), различаются только способом
распределения весов: кластеризация — поровну по кластерам, HRP — обратно дисперсии.

## 3. Как это работает (интерфейсы)

**Главное окно «Аллокация капитала»** — открывается кнопкой на главном окне (колонка
«Тестирование») или из общего журнала (`JournalUi2`). Верхние вкладки:

- **«Входящие данные»**
  - «Подгрузка данных» — добавление файлов ботов (по одному или папкой), список;
  - «Базовая доходность» — график доходности всех ботов, точность неделя/месяц, тип графика
    (абсолют/процент), диапазон дат.
- **«Расчёты»**
  - «Кластеризация по корреляции» — `min_correlation` → таблица кластеров + граф связей;
  - «Иерархический риск-паритет» — линковка/ковариация/корреляция → дендрограмма + таблица.

В каждой рабочей области — кнопка «?» с подсказкой. У кластера — кнопка «Журнал»
(позиции кластера: эквити / статистика / закрытые позиции). При закрытии окна — подтверждение.

**Сохранение результата** — кнопка «Сохранить результат» на обеих вкладках «Расчётов» пишет
файл аллокации (формат — раздел 6).

**Загрузка аллокации (применение к ботам)** — в `TesterLite`/`RobotUiLite` в последней строке
таблицы ботов кнопка «Загр. аллокацию» → окно «Загрузка аллокации»:

- «Загрузка данных» — путь к файлу + таблица кластеров/роботов из файла;
- «Установка данных» — плечо (1–6) + «Будет установлено» (бот → объём) и «Пропущено»
  (бот → причина) + «Применить».

Применение: для каждого запущенного бота ищутся параметр `Volume` и число позиций
(`Max positions` / `Positions count`), сопоставление — по `NameStrategyUniq.Split('_')[0]`,
объём = `значениеПлеча / число_позиций` (округление до 3 знаков).

## 4. MCP API и сценарии для ИИ

Открыть режим: `terminal_open_mode { mode: "allocation" }`. Далее — инструменты `allocation_*`:

- статус — `allocation_get_status`;
- боты — `allocation_bots_set` / `allocation_bots_add` / `allocation_bots_get` / `allocation_bots_clear`;
- общие настройки — `allocation_settings_get` / `allocation_settings_set` (`period`: week/month, `date_from`, `date_to`);
- кластеризация — `allocation_clustering_settings_get`/`_set` (`min_correlation`), `allocation_clustering_calculate`, `allocation_clustering_result_get`;
- HRP — `allocation_hrp_settings_get`/`_set` (`linkage` single/complete/average/ward, `covariance` sample/shrinkage, `correlation` pearson/spearman), `allocation_hrp_calculate`, `allocation_hrp_result_get`;
- файл — `allocation_result_save { file_path? }` (сохранить текущий результат в файл 100%..600%);
- применение — `allocation_load_apply { file_path, shoulder }` (прочитать файл + плечо, применить объёмы к запущенным ботам, вернуть `applied`/`skipped`).

Формат `result_get`: `clusters` = `[{ cluster_number, bots: [{ num_in_cluster, bot_name, shoulders: [100%..600%] }] }]`
+ `weights` (`bot_name` → `weight_percent`); у HRP дополнительно `allocation_merges` и `allocation_leaf_order`.

**Сценарий A — исследование (только режим аллокации):**

1. `terminal_open_mode { mode: "allocation" }`;
2. `allocation_bots_set` (файлы ботов);
3. `allocation_settings_set` (период, даты);
4. `allocation_clustering_settings_set` или `allocation_hrp_settings_set`;
5. `allocation_clustering_calculate` / `allocation_hrp_calculate`;
6. `allocation_clustering_result_get` / `allocation_hrp_result_get`.

**Сценарий B — распределение капитала (полный цикл):**

1. (в режиме аллокации) рассчитать — сценарий A, шаги 1–5;
2. `allocation_result_save { file_path }` — сохранить результат в файл;
3. (в тестере) создать/проверить роботов — `bot_create` и т.п.;
4. `allocation_load_apply { file_path, shoulder }` — применить объёмы к запущенным ботам;
5. `bot_get_params` — проверить, что `Volume` установлен.

`allocation_load_apply` работает с **запущенными** ботами (`OsTraderMaster.Master.PanelsArray`)
и не требует открытого режима аллокации; если трейдер/тестер не запущен — всё уйдёт в `skipped`.

  (`TesterLite`/`RobotUiLite`).

## 6. Формат файла аллокации

`.txt`, разделитель `;`, перевод строки `\r\n`, UTF-8. Заголовок:

```
Num cluster;Num in cluster;Name robot;100%;200%;300%;400%;500%;600%;Journal;
```

Строка кластера — номер + 10 `;`. Строка бота — `;№;имя;в100;в200;в300;в400;в500;в600;;`.
Колонки `100%..600%` — веса (доля капитала) с плечами; «Журнал» не сохраняется.
Этот же файл читает «Загрузка аллокации» и `allocation_load_apply`.
