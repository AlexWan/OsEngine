# CONTEXT_INDICATORS_MARKET_DEPTH — Стаканные и тиковые индикаторы OsEngine

Как создавать и использовать индикаторы на базе `AMarketDepth`.
Свечные индикаторы на базе `Aindicator` описаны в [`CONTEXT_INDICATORS.md`](CONTEXT_INDICATORS.md). Архитектура роботов — в [`CONTEXT_ROBOTS_ARCHITECTURE.md`](CONTEXT_ROBOTS_ARCHITECTURE.md).
Описание каждого индикатора (формулы, параметры, источники) — в [`CONTEXT_INDICATORS_MARKET_DEPTH_DESCRIPTIONS.md`](CONTEXT_INDICATORS_MARKET_DEPTH_DESCRIPTIONS.md).

## 1. Назначение и текущие границы

`AMarketDepth` — отдельная система индикаторов для стакана и ленты сделок. Она использует общие `IndicatorDataSeries`, но не наследуется от `Aindicator` и не повторяет его свечной жизненный цикл.

Текущие ограничения:

- фабрика находит public-классы из основной сборки и custom-скрипты из `Custom\IndicatorsMarketDepth\Scripts` (runtime-компиляция Roslyn);
- интеграция выполнена для `BotTabSimple` и `BotTabScreener`;
- в `StartProgram.IsOsOptimizer` мастер не загружает и не сохраняет список индикаторов;
- числовые значения серий хранятся только в памяти и не сохраняются между запусками.

### 1.1 Не переносить правила свечных индикаторов без проверки

| Аспект | `Aindicator` | `AMarketDepth` |
|---|---|---|
| Вход | `List<Candle>` и индекс свечи | Один `MarketDepth` или одна `Trade` |
| Настройка | `OnStateChange(IndicatorState.Configure)` | `OnStateChange(MarketDepthIndicatorState.Configure)` |
| Обнаружение | Атрибут `[Indicator]`, встроенные и пользовательские скрипты | Рефлексия по наследникам `AMarketDepth` в основной сборке; атрибут не требуется |
| История | Значения соответствуют свечам | Не более `HistoryDepth` значений, новый слот не чаще одного раза в секунду |
| Расчёт | `OnProcess(source, index)` | `OnProcess(depth)` и/или `OnProcessTrade(trade)` |
| Запись результата | Часто прямое обращение к `Values[index]` | `SetValue(series, value)` в последний слот |
| UI | Области свечного графика | Отдельные вкладки рядом со стаканом |

### 1.2 Карта кода

| Файл | Назначение |
|---|---|

## 2. Архитектура и поток данных

### 2.1 Стакан

Поток: источник данных → `ConnectorCandles` → `BotTabSimple._connector_GlassChangeEvent` → `MarketDepthIndicatorsMaster.Process` → `AMarketDepth.Process` → `OnProcess(depth)` → `IndicatorDataSeries`.

### 2.2 Лента сделок

Поток: источник данных → `ConnectorCandles` → `BotTabSimple._connector_TickChangeEvent` → `MarketDepthIndicatorsMaster.ProcessTrade` → `AMarketDepth.ProcessTrade` → `OnProcessTrade(trade)` → `IndicatorDataSeries`.

Мастер передаёт вход всем своим индикаторам. Фильтрацию по смыслу выполняет сам индикатор: стаканный использует `OnProcess`, тиковый — `OnProcessTrade`.

### 2.3 Тип входа

`DataSource` нужен для описания индикатора в UI:

| Значение | Назначение |
|---|---|
| `MarketDepth` | Только стакан; значение по умолчанию |
| `Trades` | Только лента сделок |
| `Both` | Индикатор использует оба входа |

Для `Trades` и `Both` свойство необходимо переопределить. Само по себе значение `DataSource` не отменяет вызовы методов базового класса.

### 2.4 UI

В окне графика робота у вкладки «Стакан» есть вложенные вкладки:

- «База» — обычный стакан;
- вкладки созданных индикаторов;
- «+» — создание нового индикатора.

Каждый индикатор получает отдельный `MarketDepthIndicatorChart`. График перерисовывается по таймеру каждые 700 мс и дополнительно по событию `NeedToRePaintEvent` после пересчёта.

## 3. Жизненный цикл `AMarketDepth`

1. `MarketDepthIndicatorsFactory.CreateByName` находит тип по имени класса и создаёт его через конструктор без параметров.
2. `Init(name, startProgram)` задаёт имя и режим запуска, создаёт встроенный параметр `HistoryDepth`, затем вызывает `OnStateChange(Configure)`.
3. В `Configure` индикатор создаёт собственные параметры и серии. При создании они читают ранее сохранённые настройки.
4. Во время работы вызываются `Process(depth)` и `ProcessTrade(trade)`.
5. После принятия настроек в UI вызываются `Save()` и `Recalculate()`.
6. При удалении `Delete()` удаляет файлы настроек, отписывает параметры и очищает серии.

### 3.1 Обязательные методы

- `OnStateChange(MarketDepthIndicatorState state)` — обязательный override. В ветке `Configure` создаются параметры и серии.
- `OnProcess(MarketDepth depth)` — обязательный override. Для тикового индикатора он может не выполнять расчёт.
- `OnProcessTrade(Trade trade)` — необязательный override для ленты сделок.
- `Description` — override с описанием для окна создания. Описание должно быть непустым.
- `DataSource` — override, если источник отличается от `MarketDepth`.

Не создавайте параметры и серии в `OnProcess` или `OnProcessTrade`: эти методы вызываются многократно.

Базовый класс оборачивает `OnStateChange`, `OnProcess` и `OnProcessTrade` в `try/catch`: исключение не роняет движок, а фиксируется в полях `ErrorCount` и `LastError`. После расчёта проверяйте `ErrorCount == 0` — это признак отсутствия ошибок в логике индикатора.

### 3.2 История и ограничение частоты

Встроенный `HistoryDepth` по умолчанию равен 60. Значение меньше или равное нулю при обработке заменяется на 60.

Для стакана:

- если с последнего принятого стакана прошло меньше секунды по `depth.Time`, обновление отбрасывается;
- для отброшенного обновления `OnProcess` не вызывается;
- для принятого обновления каждая серия получает новый последний слот, затем вызывается `OnProcess`.

Для сделок:

- `OnProcessTrade` вызывается для каждой сделки;
- новый слот серии добавляется только при переходе к следующей секунде по `trade.Time`;
- внутри одной секунды индикатор обновляет уже существующий последний слот.

Общие правила:

- перед расчётом новый слот заполняется предыдущим значением серии;
- после добавления старые значения удаляются, пока не останется не более `HistoryDepth`;
- время каждой точки хранится в `IndicatorDataSeries.Times` и выровнено по индексу с `Values`; график использует его для оси X;
- `SetValue(series, value)` записывает результат именно в последний слот и безопасно игнорирует пустую серию.

Для тикового агрегата накапливайте состояние внутри индикатора: базовый класс передаёт каждую сделку, но не хранит архив сделок за секунду.

### 3.3 Что делает `Recalculate`

`Recalculate` не восстанавливает полную историю входных данных:

- обрезает серии до `HistoryDepth`;
- если ранее был принят стакан, повторно вызывает `OnProcess` по последнему из них;
- вызывает `RePaint()`.

Последняя сделка отдельно для повторного расчёта не сохраняется. Не описывайте `Recalculate` как полный пересчёт истории, аналогичный свечному `Reload`.

## 4. Добавление нового встроенного индикатора

1. Создайте файл в `OsEngine/IndicatorMarketDepth/Scripts/`.
2. Имя файла должно совпадать с именем класса.
3. Используйте namespace `OsEngine.IndicatorMarketDepth.Scripts`.
4. Класс должен быть `public`, не абстрактным и наследоваться от `AMarketDepth`.
5. Оставьте доступный конструктор без параметров. Явный конструктор не обязателен, если компилятор создаёт его автоматически.
6. Атрибут `[Indicator]` не добавляйте: эта фабрика его не использует.
7. Переопределите `Description`, `OnStateChange` и `OnProcess`.
8. Для ленты переопределите `DataSource` и `OnProcessTrade`.
9. В `Configure` создайте параметры и серии с устойчивыми именами.
10. Реализуйте расчёт и запись всех выходных серий через `SetValue`.

Ручная регистрация в фабрике не нужна. После сборки и перезапуска OsEngine public-наследник `AMarketDepth` из основной сборки автоматически появляется в `GetIndicatorsNames()` и в окне создания.

### 4.1 Рецепт стаканного индикатора

- Оставьте `DataSource = MarketDepth`.
- Используйте `depth.Bids` и `depth.Asks` в `OnProcess`.
- По соглашению текущих индикаторов нулевой элемент используется как лучший уровень.
- Поля `Price`, `Bid` и `Ask` уровня стакана имеют тип `double`; для денежных расчётов выполняйте явное преобразование к `decimal`.
- Ограничивайте цикл и количеством доступных уровней, и параметром глубины.
- Обрабатывайте пустые стороны, нулевой объём, некорректные цены и деление на ноль.
- При каждом вызове записывайте все серии, включая нейтральное значение при нехватке данных.

### 4.2 Рецепт тикового индикатора

- Установите `DataSource = Trades`.
- Реализуйте расчёт в `OnProcessTrade`.
- Используйте `trade.Time`, `trade.Price`, `trade.Volume`, `trade.Side` и при необходимости идентификаторы сделки.
- Помните: метод вызывается для каждой сделки, а не один раз в секунду.
- Храните накопители секунды в полях индикатора и сбрасывайте их по своему алгоритму.
- `OnProcess` всё равно обязателен по контракту, даже если стакан не нужен.

### 4.3 Индикатор с источником `Both`

Используйте `Both` только если расчёту действительно нужны оба потока. `Process` и `ProcessTrade` работают с одними и теми же `DataSeries` и самостоятельно добавляют слоты. Продумайте, как синхронизируются значения и какой вход является ведущим, иначе результат будет зависеть от чередования событий.

## 5. Параметры

Параметры создаются только в `OnStateChange(Configure)`:

| Метод | Тип | Доступ к значению |
|---|---|---|
| `CreateParameterInt(name, value)` | `ParameterMarketDepthInt` | `ValueInt` |
| `CreateParameterDecimal(name, value)` | `ParameterMarketDepthDecimal` | `ValueDecimal` |
| `CreateParameterString(name, value)` | `ParameterMarketDepthString` | `ValueString` |
| `CreateParameterStringCollection(name, value, collection)` | `ParameterMarketDepthString` с выпадающим списком | `ValueString`, `ValuesString` |
| `CreateParameterBool(name, value)` | `ParameterMarketDepthBool` | `ValueBool` |

Правила:

- имя параметра должно быть уникальным внутри индикатора и не меняться между версиями без миграции настроек;
- `HistoryDepth` уже создан базовым классом до `Configure`; не создавайте второй параметр с таким именем;
- значения по умолчанию сохраняются в свойствах `Value*Default`;
- `DoDefault()` возвращает значение по умолчанию;
- изменение значения вызывает `ValueChange` у параметра и `ParametersChangeByUser` у индикатора;
- после программного изменения параметров из робота вызовите `Save()` и `Recalculate()`; одного присваивания недостаточно.

## 6. Выходные серии

Серия создаётся через `CreateSeries(name, color, chartPaintType, isPaint)` в `Configure`.

| Свойство | Назначение |
|---|---|
| `Name` | Уникальное имя серии внутри индикатора и ключ сохранения визуальных настроек |
| `Color` | Цвет на графике |
| `ChartPaintType` | Тип отрисовки |
| `IsPaint` | Нужно ли рисовать серию; расчёт при этом не отключается |
| `Values` | Значения `List<decimal>` |
| `Times` | Время каждой точки `List<DateTime>`, выровнено по индексу с `Values` |
| `Last` | Последнее значение; при пустом списке возвращает 0 |
| `LineWidth` | Толщина линии; сохраняется в настройках |
| `ZeroIsGap` | Нули как разрывы линии; сохраняется в настройках |

Поддерживаемые стаканным графиком типы: `Line`, `Column`, `Point`. Тип `Candle` присутствует в общем enum и в списке настроек, но `MarketDepthIndicatorChart` его не рисует — для новых индикаторов не используйте его.

Порядок создания серий должен быть стабильным: график формирует внутренние имена по имени индикатора и индексу серии. Не меняйте порядок без необходимости.

`CanReBuildHistoricalValues` принадлежит общему `IndicatorDataSeries`, но текущий стаканный график этот флаг не использует.

## 7. Сохранение и удаление

| Данные | Файл |
|---|---|
| Параметры одного индикатора | `Engine\{IndicatorName}MarketDepthParametrs.txt` |
| Визуальные настройки серий | `Engine\{IndicatorName}MarketDepthValues.txt` |
| Список индикаторов источника | `Engine\{TabName}MarketDepthIndicators.txt` |

Несмотря на название, `MarketDepthValues.txt` содержит имя, цвет, тип и `IsPaint` серий, а не числовые `Values`.

`MarketDepthIndicatorsMaster`:

- `CreateIndicator(typeName, name)` возвращает `null` при неизвестном типе или повторном имени;
- после создания сохраняет список и вызывает `IndicatorAddedEvent`;
- `DeleteIndicator` отписывает индикатор, удаляет его настройки, сохраняет список и вызывает `IndicatorRemovedEvent`;
- `Clear` удаляет все индикаторы;
- `Delete` очищает индикаторы и удаляет файл списка;
- `BotTabSimple.Delete()` вызывает `Delete()` мастера.

В режиме `IsOsOptimizer` список не загружается и не сохраняется, а `Save()` и файловое удаление отдельного индикатора пропускаются.

## 8. Использование из робота

Доступ предоставляет `BotTabSimple.MarketDepthIndicators`.

Основной сценарий:

1. Создайте индикатор один раз при инициализации робота через `CreateIndicator`, если он не создаётся вручную в UI.
2. Сохраните ссылку на экземпляр или находите его в `MarketDepthIndicators.Indicators` по `Name`.
3. Перед чтением проверьте ссылку, наличие нужной серии и `Values.Count`.
4. Прочитайте `DataSeries[index].Last` или конкретный элемент `Values`.
5. Не изменяйте `Values` из робота: этим списком управляет базовый класс.

`Last` возвращает 0 для пустой серии. Если ноль является допустимым результатом, проверка `Values.Count` обязательна.

События стакана и сделок могут приходить из фоновых потоков. Не выполняйте длительные операции в обработчиках и не перебирайте изменяемый список значений без синхронизации. Общее состояние робота защищайте согласно [`CONTEXT_CODING_GUIDELINES.md`](CONTEXT_CODING_GUIDELINES.md).

## 9. Описание и научная карточка

`Description` показывается в окне создания. Для встроенных индикаторов используйте локализацию через `OsLocalization.ConvertToLocString` с английским и русским вариантами.

Для каждого нового индикатора отдельно фиксируйте:

- определение и экономический смысл;
- формулу и диапазон результата;
- необходимые входные данные;
- параметры и значения по умолчанию;
- поведение при пустых или некорректных данных;
- ограничения и ложные интерпретации;
- ссылки на первоисточники или документацию платформ.

Не выдумывайте название или формулу «по аналогии»: общеупотребимые названия должны совпадать с принятым определением.

## 11. Частые ошибки

| Ошибка | Последствие | Как правильно |
|---|---|---|
| Добавить `[Indicator]` и считать этого достаточным | Атрибут не участвует в обнаружении | Нужен public-наследник `AMarketDepth` в основной сборке или в `Custom\IndicatorsMarketDepth\Scripts` |
| Положить custom-скрипт не в ту папку | Индикатор не появится | Custom-скрипты класть в `Custom\IndicatorsMarketDepth\Scripts` (рядом с `.exe`) |
| Создавать параметры в расчёте | Повторное создание и поломка настроек | Только `OnStateChange(Configure)` |
| Создать второй `HistoryDepth` | Конфликт с встроенным параметром | Использовать свойство `HistoryDepth` |
| Записывать новый элемент `Values` вручную | Нарушение лимита и троттлинга | Базовый класс добавляет слот; индикатор вызывает `SetValue` |
| Считать `OnProcessTrade` секундным событием | Неверная агрегация | Он вызывается для каждой сделки |
| Считать `Recalculate` полным пересчётом | Ожидание несуществующей истории | Это обрезка, повтор последнего стакана и перерисовка |
| Использовать `Candle` как тип серии | Серия не будет нарисована | `Line`, `Column` или `Point` |
| Читать `Last` без проверки пустой серии | Нулевое значение принято за расчёт | Проверить `Values.Count` |
| Создавать индикатор на каждом событии | Дубликаты, файлы и лишняя работа | Создание один раз, расчёт — в обработчиках |
| Игнорировать пустой стакан и деление на ноль | Исключения и некорректные значения | Защитные проверки до формулы |
